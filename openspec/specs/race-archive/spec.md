## Requirements
### Requirement: Локальне збереження запису гонки
Система MUST зберігати кожен запис гонки у localStorage браузера під ключем `races_db_v1` у форматі JSON-масиву. Новий запис додається на початок масиву.

#### Scenario: Збереження запису після гонки
- **WHEN** гонка завершена і викликано persist
- **THEN** запис із полями `id`, `dateIso`, `finishMeters`, `runner1`, `runner2`, `winner`, `time1`, `time2`, `laps1`, `laps2` з'являється першим у localStorage під ключем `races_db_v1`

#### Scenario: Відсутній або пошкоджений localStorage
- **WHEN** значення за ключем `races_db_v1` відсутнє або не є валідним JSON
- **THEN** система вважає архів порожнім і не кидає помилку

---

### Requirement: Опційна синхронізація із зовнішнім API
Коли задано `VITE_ARCHIVE_API_URL`, система MUST надсилати копію кожного запису гонки на сервер (POST `/api/races`) після локального збереження. Відсутність або недоступність API MUST NOT впливати на роботу UI.

#### Scenario: API налаштовано і доступний
- **WHEN** `VITE_ARCHIVE_API_URL` задано і гонка завершена
- **THEN** система надсилає запис на сервер у фоні; помилка мережі ковтається без сповіщення

#### Scenario: API не налаштовано
- **WHEN** `VITE_ARCHIVE_API_URL` не задано
- **THEN** система зберігає лише локально, без будь-яких мережевих запитів

---

### Requirement: Відображення архіву результатів
Система MUST завантажувати та відображати список гонок у вигляді таблиці з полями: дата, суперники, дистанція фінішу, часи обох учасників, переможець.

#### Scenario: Джерело — зовнішній API
- **WHEN** `VITE_ARCHIVE_API_URL` задано і GET `/api/races` повертає успішну відповідь
- **THEN** відображається таблиця із записами сервера з міткою «З сервера»

#### Scenario: Fallback на localStorage при помилці API
- **WHEN** запит до API повертає помилку або недоступний
- **THEN** відображається таблиця із локальних записів без мітки «З сервера»

#### Scenario: Джерело — лише localStorage
- **WHEN** `VITE_ARCHIVE_API_URL` не задано
- **THEN** відображається таблиця із локальних записів

---

### Requirement: Розгортання лап у таблиці
Система MUST надавати можливість розгорнути деталі кожного запису гонки і переглянути таблицю лап обох учасників (дистанція, час).

#### Scenario: Розгортання рядка
- **WHEN** користувач натискає кнопку розгортання рядка гонки
- **THEN** під рядком відображаються дві таблиці лап: для учасника 1 і учасника 2

---

### Requirement: Видалення запису (лише локальний режим)
Система MUST надавати можливість видалити окремий запис або очистити весь архів, якщо джерело даних — localStorage. У режимі API видалення MUST бути недоступним.

#### Scenario: Видалення одного запису
- **WHEN** джерело — localStorage і користувач натискає «Видалити» для конкретного запису
- **THEN** запис видаляється з localStorage і зникає з таблиці

#### Scenario: Очищення всього архіву
- **WHEN** джерело — localStorage і користувач натискає «Очистити архів»
- **THEN** всі записи видаляються з localStorage і таблиця стає порожньою

#### Scenario: Спроба видалення в режимі API
- **WHEN** джерело — зовнішній API
- **THEN** кнопки видалення недоступні або приховані

---

### Requirement: Серверний API прийому записів
Сервер MUST приймати нові записи гонок через POST `/api/races` з повною валідацією тіла запиту та повертати 201 при успіху або відповідний код помилки.

#### Scenario: Валідний запис
- **WHEN** POST `/api/races` отримує тіло з валідними полями `id`, `dateIso`, `finishMeters`, `runner1`, `runner2`, `winner`, `time1`, `time2`, `laps1`, `laps2`
- **THEN** сервер зберігає запис у SQLite і повертає 201 з `{ id }`

#### Scenario: Невалідне тіло запиту
- **WHEN** POST `/api/races` отримує тіло із відсутніми або некоректними полями
- **THEN** сервер повертає 400 з описом помилки

#### Scenario: Дублікат за id
- **WHEN** POST `/api/races` отримує запис із `id`, що вже існує в базі
- **THEN** сервер повертає 409

---

### Requirement: Серверний API отримання записів
Сервер MUST повертати список всіх збережених записів гонок через GET `/api/races` у форматі JSON-масиву, відсортованого за датою (новіші першими).

#### Scenario: Отримання списку записів
- **WHEN** клієнт надсилає GET `/api/races`
- **THEN** сервер повертає 200 з масивом всіх записів у форматі `RaceRecord[]`
